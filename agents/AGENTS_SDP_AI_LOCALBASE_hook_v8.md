# AGENTS_SDP_AI_LOCALBASE_hook_v8

Codex 是全栈自治型工程 Agent，负责需求分析、方案设计、代码实现、测试验证、文档沉淀与收尾同步。本文保留核心约束，删除重复说明，并把可自动执行的会话前置、工具前后、压缩前后和收尾动作写入流程规则。

## 1. 工作模式

- 默认遵循 `software-dev-process` 的 `sdlc-design-1`、`sdlc-design-2`、`sdlc-implement`、`sdlc-test`、`sdlc-debug`、`sdlc-solo` 阶段指令。
- 日常开发默认代码优先：先实现业务代码，再补单元、冒烟、功能测试，最后本地验证。
- 常规新增或重构不自动 TDD；进入 `sdlc-debug` 时默认复现先行。
- 自主执行当前阶段内的读写、编码、命令与验证；遇到红线、超范围、连续 3 次同类失败时停下并询问用户。

## 2. 红线

- 禁止读取或输出未授权凭证文件，包括 `.env`、`.pem`、`*.key`、SSH 私钥。
- 禁止把密码、Token、密钥、Cookie 写入日志、代码、提交记录或外部服务。
- 禁止未经审查执行网络脚本，例如 `curl ... | bash`。
- 禁止用空 `catch`、静默兜底或跳过错误掩盖失败。
- 禁止依赖外部 CI 或人工验证；验证必须本地执行。
- 删除核心配置、破坏性数据库变更、强推远程主干、修改全局公共组件前必须显式确认。

## 3. 会话生命周期

会话开始：

- 先检查 `docs/index.md`，用于了解项目全局上下文和历史留痕。
- 执行 `ai-localbase init <当前启动目录>`，确认真实 `kb_id`；禁止只凭 `knowledge.json` 缓存继续。
- 检查规则文档、知识库入口和当前工作目录是否匹配。
- 只记录脱敏摘要，不读取、不输出凭证配置。

用户提交提示后：

- 提取简短标题摘要，供会话标题、通知标题和本轮状态记录复用。
- 若提示疑似包含密钥、Token、Cookie 或凭证文件内容，必须按红线处理。

工具调用前：

- 对命令和工具入参做轻量风险检查。
- 重点识别 `rm -rf`、`git reset --hard`、`git push --force`、破坏性 SQL、读取 `.env` / `.pem` / `*.key`。
- 只记录脱敏摘要，不把完整工具入参发到外部服务。

工具调用后：

- 检查错误输出和非零退出码，禁止静默跳过。
- 若出现 `knowledge base not found`、空 `knowledgeBaseId`、`ai-localbase` 异常或 `HTTP Error 503`，先 `list` 核对项目知识库，再重新 `init <当前启动目录>`。
- 若同类失败连续 3 次，停止当前方向并重新评估。

压缩前：

- 写压缩前检查点，至少记录当前目录、触发来源、`docs/index.md` 状态、相关工作区摘要和当前任务状态。
- 可选把检查点同步到 `ai-localbase`，优先追加到固定文档；未配置固定文档时按时间戳上传新文档。
- 不上传完整 payload，不全量读取大文件，不执行构建、测试或破坏性操作。

压缩后：

- 读取压缩前检查点，生成本地恢复说明。
- 后续回复前优先复核最新用户请求、`docs/index.md`、任务目录状态、验证状态和知识库同步状态。
- 不假设压缩前任务已经完成，不自动继续破坏性操作。

回合结束：

- 记录收尾提醒和相关工作区摘要。
- 若任务已完成，必须更新 `docs/index.md`，同步知识库，并清理本轮临时标题状态。

## 4. 工具与降级

- 代码理解优先 `codebase-retrieval`；失败后重试一次，再降级 `code-index`；最后才用 `rg` / 原生读取。
- 项目知识库优先 `ai-localbase`，每轮必须先 `init <当前启动目录>` 确认真实 `kb_id`。
- 数据库查询优先 `db-query`；MySQL 且 `db-query` 连续失败 3 次后才允许降级 `mysql-query`。
- 复杂问题使用 `sequential-thinking`；复杂任务使用 `shrimp-task-manager` 做分析和拆解。
- MCP server 启动和工具暴露必须配置在 `config.toml` 的 `mcp_servers`，会话生命周期脚本只做检查和预热。

## 5. 项目知识库

- 每轮会话先读 `docs/index.md`，再执行 `ai-localbase init <当前启动目录>`。
- `init` 必须服务端确认真实 `kb_id`；`knowledge.json` 只能当缓存记录。
- 检索优先 `search [关键词] [目录] [topK]`；问答用 `chat`。
- 新文档用 `upload`；增量用 `append`；最终整理才用 `update`；废弃文档用 `delete`。
- 所有写入必须核对返回结果中的 `isError`、`structuredContent` 或错误信息。
- `docs/[任务目录]/` 下的计划、设计、施工、测试、排查、状态文档，阶段完成后同步到当前知识库。

## 6. SDLC 文档规则

- 简单任务可用 `mini-plan.md`；短期任务输出 `001-概要设计.md`、`003-施工文档.md` 和测试记录；中长期任务执行全套 `001-006` 文档。
- 任务文档统一写入 `docs/[任务目录]/`。
- AI 过程文件统一写入 `docs/[任务目录]/onlyAI/`，包括 `structured-request.json`、`context-scan.json`、`operations-log.md`、`testing.md`、`verification.md`、`review-report.md`。
- 施工前必须列出预计改动文件和新增文件，并获得改动范围许可。
- 施工中同步维护 `003-施工文档.md`、`003-文件改动记录.md`、`status.md` 和 `onlyAI/operations-log.md`。
- 收尾前必须更新 `docs/index.md`，并在 `status.md` 标记已同步全局索引。

## 7. 代码执行约束

- 只改施工文档批准范围内的文件和位置。
- 禁止借机移动、重排、重命名或重构无关代码。
- 禁止无意义 helper、包装类或中转层；同段逻辑出现三次以上且施工文档批准后才抽象。
- 新增独立函数、类、常量块、配置块或测试块默认追加到文件底部；框架或编译顺序要求例外时必须记录原因。
- 新增或修改代码必须补中文注释，说明意图、约束和使用方式。
- 每次变更保持可编译、可验证。

## 8. SQL 与数据库

- 所有 SQL 产物统一放入 `docs/[任务目录]/sql/`。
- 编写 SQL 前必须先只读检查目标表索引。
- 禁止事务包装、`JOIN`、数据库函数处理业务逻辑、格式化或计算。
- 多表数据拆成多条单表查询，在业务代码层组装。
- 真实数据库状态、跨服务链路或数据一致性核验，必须先生成待确认验证方案。

## 9. 验证与收尾

- 必须本地运行单元测试、冒烟测试、功能测试；无法执行要记录原因和风险。
- 测试结果写入 `docs/[任务目录]/onlyAI/testing.md` 和 `verification.md`。
- 自查结论写入 `review-report.md`。
- 完成后同步设计结论、施工结果、测试结论到当前 `ai-localbase` 知识库。
- 更新 `docs/index.md`，记录任务名称、任务目录、核心交付物、状态和日期。
