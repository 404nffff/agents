# 并行任务判定清单

> 用于 `software-dev-process-mutil-agent` 在派发多个子代理前判断“当前任务是否允许并行”。主控必须逐项检查，任一阻断项命中则退回串行。

## 一、先决条件

- [ ] 任务已经进入明确的 SDLC 阶段，不是模糊探索状态
- [ ] `003-施工文档.md` 已经存在，且每个候选并行任务都有独立任务 ID
- [ ] 每个候选并行任务都已写明 `执行角色`、`Agent 类型`、`允许改动/读取文件`、`交付物`、`复核角色`
- [ ] 主控已经读取对应角色文件，知道每个子代理的职责边界

## 二、允许并行的必要条件

- [ ] 任务之间的允许改动文件完全不重叠
- [ ] 任务之间没有前后产物依赖
- [ ] 任务之间不共享同一个数据库脚本、迁移步骤或发布动作
- [ ] 任务之间不要求同时修改同一份公共配置
- [ ] 任务执行失败时，可以独立回退，不会污染其他任务结果

## 三、阻断项

只要命中以下任一项，就必须串行：

- [ ] 多个任务会修改同一文件
- [ ] 多个任务会修改同一模块中的强耦合逻辑
- [ ] 下游任务依赖上游任务新增的接口、字段或类型
- [ ] 多个任务会竞争同一个临时资源、数据库状态或测试环境
- [ ] 当前阶段还没有把任务边界写入 `003-施工文档.md`
- [ ] 主控无法为每个子代理定义清晰的验收标准

## 四、建议策略

- 设计阶段：优先并行 `explorer`，做只读扫描和风险识别
- 实现阶段：优先串行；只有文件边界完全独立的 `worker` 才并行
- 测试阶段：可以按测试域并行，但每个测试域必须有独立输出
- Debug 阶段：可以并行排查多个独立现象，但真正修复仍应谨慎串行

## 五、输出结论模板

```markdown
并行判定：允许 / 不允许

原因：
1. [说明关键判断]
2. [说明阻断项或通过项]

并行任务组：
- G-01: [任务 ID 列表]
- G-02: [任务 ID 列表]

主控决定：
- [例如：T-02 与 T-03 文件范围不重叠，允许两个 worker 并行]
- [例如：T-04 依赖 T-02 产出的类型定义，必须串行等待]
```
